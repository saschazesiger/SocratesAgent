Terminal engine

Socrates keeps every Shell inside tmux, which is what lets a terminal outlive the browser, the phone and Socrates itself. It is not optional and there is no fallback.

Updates

Once a day, and after every boot, the updater brings Socrates, the three programs, Go, Node, code-server and cloudflared up to date. It runs beside Socrates rather than inside it, so a run that updates Socrates restarts it and the sessions stay up.

Backup

              
            

            
Everything Socrates keeps is in its data directory on this machine: the chats, the accounts with their sign-ins and transcripts, the settings. While anything changes, it is backed up to an S3 bucket every few minutes — encrypted here with your passphrase, and only what changed goes up. Working directories are not in the backup; they live in git. A new machine is restored from its setup page.

Accounts

            
The accounts the chats run on: subscriptions and API keys, for each agent. A chat can move to another account of its agent while it is open, and the lists offer them in this order — drag a row by its handle to change it. Every account of an agent shares that agent's conversations; a sign-in stays with its account.

            

            
Changes here take effect at once. A subscription signs in with the agent's own page; an API key is kept encrypted on this machine and is never shown again.

Voice

            
Your recording is transcribed by an OpenRouter model. Reading an answer back is Google Cloud Text-to-Speech: one API key of its own, and the Standard voices are free for the first four million characters a month.

            

              

                
                
                Create one at openrouter.ai/keys. It transcribes what you dictate, and it runs the models under Status & naming: the spoken status and the session names, and with the turn outcome switched on the check of each chat's turn — which sends the chat's last instruction, answer, calls and task list to OpenRouter. The coding programs bring their own credentials.
              

              

                
                

                A dedicated transcriber such as openai/gpt-transcribe, or a chat model that accepts audio such as google/gemini-2.5-flash.
              

              

                

                  
                  
                  One setting for everything Socrates says: how a recording is transcribed, which of the two voices below reads an answer out loud, and which language an answer is written in.
                

                

                  
                  
                  Sent with the recording when a chat model does the transcribing. A dedicated transcription model is given the language instead.
                

              

            


            

              
Reading answers out loud

              

                

                  
                  
                  This is what reads answers out loud. The five steps below are how to get one. Save before you test: both buttons use the key the server has stored, not the one typed here.
                

                

                  

                    
                    
                  

                  

                    
                    
                  

                  

                    
                    
                    1 is the voice's own pace; Google accepts 0.25 to 4.
                  

                

                Only names with Standard in them are in the four million character free tier. WaveNet and Neural2 voices sound better and have a much smaller allowance of their own — a million characters a month — Studio voices 100,000 bytes a month, and all of them cost more per character beyond it. The full list is in Google's supported voices.
                

                  
                

                

                  
                  
                

              

            


            

              Getting a Google Cloud key
              

                
    
                  
  1. Open the Google Cloud console and sign in. Create a project or pick one. Billing has to be enabled on that project for the API to answer at all — Standard voices still include four million characters a month free, and only what goes beyond that is charged.
    2. 
                  
  2. Enable the API: APIs & Services → Library, search for “Cloud Text-to-Speech API”, press Enable — or go straight to it.
    3. 
                  
  3. Create the credential: APIs & Services → Credentials → Create credentials → API key. Copy the key.
    4. 
                  
  4. Recommended: edit that key, and under API restrictions restrict it to the Cloud Text-to-Speech API. A key that leaks can then do nothing else.
    5. 
                  
  5. Paste it above, save, and press “Test voice output”.
    6. 
                

                
What you have used is under APIs & Services → Enabled APIs & services → Cloud Text-to-Speech API → Quotas & System Limits, and Metrics beside it.

              

            

          


          
          

            
Status & naming

            
Status has a model read what a chat is doing, or the screen of a Shell, and say it in one or two sentences, which the voice above reads out loud. The namer calls a chat after its first message, once.

            

              

                

                  
                  

                  Asked for a sentence about a session, so a fast, cheap model is the right one — google/gemini-2.5-flash is the default.
                

                

                  
                  

                  Asked for a handful of words once per session, so the cheapest model will do — google/gemini-2.5-flash-lite is the default.
                

                

                  
                  

                  Judges how each chat's turn left the work when the switch below is on. It runs on every turn, so a fast, cheap model is the right one — google/gemini-3.5-flash is the default.
                

              

              

                
                When a chat's turn ends, the outcome model judges whether the task is complete, partly done with open todos, waiting on you, or blocked, and the chat shows it. It is sent the chat's last instruction, its answer, the calls it made and its task list. Notifications wait up to 45 seconds for the verdict.
