Storage

Socrates keeps its own state in an S3 bucket: the settings, the password, sign-ins, profiles, push subscriptions and every session with its prepared prompt. It is encrypted on this machine with your passphrase before it leaves. The data directory keeps the rest — the programs' own logins and transcripts, the workspaces and tmux.

Profiles

A profile is a separate set of sign-ins for Claude Code, Codex and OpenCode - a business account beside a private one. The new-session sheet asks which profile a session runs in, in the order of this list - drag a row by its handle to change it - and a session keeps that profile for its whole life. Settings, instructions, skills, plugins and MCP servers are shared with the default profile; accounts and conversations are not.

Changes here take effect at once. To sign in, start a session in the profile: Claude Code asks by itself, and a container Shell in the profile is where codex login --device-auth and opencode auth login sign the other two in.

Voice

Your recording is transcribed by an OpenRouter model. Reading an answer back is Google Cloud Text-to-Speech: one API key of its own, and the Standard voices are free for the first four million characters a month.

Create one at openrouter.ai/keys. It transcribes what you dictate, and it runs the models under Status & naming: the spoken status and the session names, Home's summaries and questions — which send the screen of every coding session to OpenRouter, and with the turn outcome switched on also Claude's last instruction, answer and task list — and the operator that types your answers into a session. The coding programs bring their own credentials.
A dedicated transcriber such as openai/gpt-transcribe, or a chat model that accepts audio such as google/gemini-2.5-flash.
One setting for everything Socrates says: how a recording is transcribed, which of the two voices below reads an answer out loud, and which language an answer is written in.
Sent with the recording when a chat model does the transcribing. A dedicated transcription model is given the language instead.
This is what reads answers out loud. The five steps below are how to get one. Save before you test: both buttons use the key the server has stored, not the one typed here.
Only names with Standard in them are in the four million character free tier. WaveNet and Neural2 voices sound better and have a much smaller allowance of their own — a million characters a month — Studio voices 100,000 bytes a month, and all of them cost more per character beyond it. The full list is in Google's supported voices.
How fast the voice reads. 1 is its own pace; Google accepts 0.25 to 4.

Getting a Google Cloud key

  1. Open the Google Cloud console and sign in. Create a project or pick one. Billing has to be enabled on that project for the API to answer at all — Standard voices still include four million characters a month free, and only what goes beyond that is charged.
  2. Enable the API: APIs & Services → Library, search for “Cloud Text-to-Speech API”, press Enable — or go straight to it.
  3. Create the credential: APIs & Services → Credentials → Create credentials → API key. Copy the key.
  4. Recommended: edit that key, and under API restrictions restrict it to the Cloud Text-to-Speech API. A key that leaks can then do nothing else.
  5. Paste it above, save, and press “Test voice output”.
What you have used is under APIs & Services → Enabled APIs & services → Cloud Text-to-Speech API → Quotas & System Limits, and Metrics beside it.

Status & naming

Status has a model read the screen of a session and say what it is doing, in one or two sentences, which the voice above reads out loud. The namer reads the first screen a session answers on and calls the session after it, once.

Asked for a sentence about a screen, so a fast, cheap model is the right one — google/gemini-2.5-flash is the default.
Asked for a handful of words once per session, so the cheapest thing that can read a screen will do — google/gemini-2.5-flash-lite is the default.
Reads the screen of every coding session for Home: a line about what it is doing, and the question it is asking with its choices. It runs on every turn, so a fast, cheap model is the right one — google/gemini-3.5-flash is the default.
When a turn ends, the same read also judges whether the task is complete, partly done with open todos, waiting on you, or blocked, and the session shows it. For Claude it is also sent the last instruction, the last answer and the task list. Notifications wait up to 45 seconds for the verdict.
Types the answer you chose on Home into the session, key by key, and only ever because you tapped it. Reading a terminal menu is where a cheap model goes wrong, so this one is capable on purpose — anthropic/claude-sonnet-5.5 is the default.
